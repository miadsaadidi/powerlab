# User Interaction & Deployment Rules (Strict Non-Negotiable)

1. **Answer Direct Questions Directly:**
   - When the user asks a question (e.g., status questions, informational queries, "did you push to vercel? yes/no"), answer the question directly with clear, concise facts.
   - Do NOT run background scripts, trigger builds, or execute deployments while answering a question.

2. **Markdown Documentation & SEO Plans Are NOT Code:**
   - Markdown files (`.md`), outreach plans, SEO schedules, and documentation updates are NOT executable code.
   - Do NOT run unit tests (`npm test`), typechecks, or production builds (`npm run build`) for markdown, content, or SEO plan changes.
   - Never trigger unrequested production builds or deployments.

3. **No Unsolicited Deployment or Production Actions:**
   - Do NOT engage in modifying production environments or triggering build/deployment pipelines unless the user explicitly commands you to do so (e.g., "deploy to vercel", "run the build", "fix this bug").
   - Always confirm before performing external or production actions if not explicitly commanded.

4. **Mandatory Core Authority Protocol for Daily SEO/Publishing Plans:**
   - Whenever asked for "today's plan", a daily task list, or SEO execution status, you MUST check and present actionable items across ALL active Core Authority channels:
     1. **Medium (DA 96):** 1 technical teardown every 2 days.
     2. **DEV.to (DA 91):** 1 developer/TypeScript engineering post every 2 days (starts Sept 4).
     3. **Internet Archive (DA 99):** 1 permanent open-access PDF/whitepaper/methodology archive upload every 2 days (starts Sept 4).
     4. **Harvard Dataverse (DA 93):** 1 open benchmark research dataset deposit every week (starts Sept 4).
     5. **Academia.edu (DA 93):** 2×/week technical discussion updates & working paper syndications.
     6. **Institutional Outreach (Daily 5):** 5 targeted emails + 72h/7-day follow-up tracking.
5. **Conversational Pacing & Explicit Confirmation Before Execution:**
   - When discussing strategy, planning, or workflows, maintain the conversation naturally without abruptly dumping full execution payloads or large walls of copy-paste text.
   - Present clear, bite-sized steps outlining what will be done.
   - Always ask for explicit confirmation before generating large content, proceeding to the next platform, or starting execution.
   - Never assume or rush ahead of the user's current pace.

6. **Strict Outreach Review Gate (NEVER Dump Email Drafts Unprompted):**
   - When the user says "outreach" or discusses outreach, show ONLY the candidate recipient list (Names, Publications, and 1-line Topics).
   - NEVER write, draft, or output full email bodies until the user explicitly reviews and approves the targets.
